# Security Policy

## Supported Versions

| Version | Supported          |
|---------|--------------------|
| 4.0.x   | ✅ Active support  |
| < 4.0   | ❌ Not supported   |

## Reporting a Vulnerability

We take security vulnerabilities seriously. If you discover a security issue in BugReaper X, please report it responsibly.

### 📧 Email

**security@bugreaper-x.ca**

Do **not** open a public GitHub issue for security vulnerabilities.

### ⏱ Response Timeline

- **48 hours**: Initial acknowledgment
- **7 days**: Assessment and patching timeline
- **30 days**: Public disclosure (if applicable) after patch release

### 🔒 What to Include

- Description of the vulnerability
- Steps to reproduce
- Affected versions
- Proof of concept (if available)
- Your contact information

### 🏆 Recognition

We believe in crediting security researchers who report valid vulnerabilities. With your permission, we will:

- Add your name to our Hall of Fame
- Mention you in the release notes
- Offer a BugReaper X swag package (where available)

## 🛡️ Built-in Protections

BugReaper X includes multiple layers of protection:

1. **Anti-Clone System** — Domain-locked bootstrap guardian prevents unauthorized hosting
2. **Honeypot System** — Decoy credentials and endpoints that detect scrapers
3. **Code Obfuscation** — Max-level obfuscation with control flow flattening
4. **Content Security Policy** — Strict CSP blocking XSS and injection
5. **Debug Protection** — Anti-devtools and debugger traps

These systems are designed to protect our users and infrastructure. Bypassing them for legitimate research purposes? Contact us first.

## 📋 Disclosure Policy

- **Private disclosure**: Preferred for all security issues
- **Coordinated disclosure**: We will work with you to set a timeline
- **Public disclosure**: Only after a fix is released and users have had reasonable time to update
